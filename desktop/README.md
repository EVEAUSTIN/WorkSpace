# Windows 桌面版 0.2：SQLite + CloudBase 同步

本机 SQLite 为离线副本，CloudBase 同步备忘录、储物柜（含库存记录）、晨起提醒、每日记录、药箱、游玩打卡和笔记。使用现有 public.qijian_records 表及 RLS；无需重建表，不关闭权限校验。

AI API 密钥、客户端登录配置、天气及文献缓存和当前会话 AI 对话不作为业务记录上传。笔记内嵌的媒体随笔记 JSON 同步；尚未实现独立的大附件分块上传，服务端大小限制或超时会显示失败并保留本地内容，不代表附件已同步。

## 更新已有安装（两台电脑分别操作）

1. 关闭工作台窗口。
2. 重新下载 GitHub main 分支 ZIP，先解压到临时目录。
3. 将 ZIP 工程根目录中的文件和文件夹复制到原工程根目录，允许覆盖。保留本机 node_modules 文件夹；不要删除或覆盖 `%APPDATA%\qijian-workspace`，这里有数据库及会话数据。
4. 此次没有变更依赖版本，已有 node_modules 可直接使用。桌面快捷方式继续指向原工程目录，不要指向临时解压目录。
5. 再用快捷方式启动。如果首次安装、缺少依赖，才在工程目录运行 `npm.cmd ci`。

开发版与打包版显式使用相同的 userData 路径 `%APPDATA%\qijian-workspace`；移动工程文件不移动 SQLite 数据库。现有 SQLite 表保留，只新增 sync_history 历史表。

## 首次安装

使用 Node.js 24 LTS。在含有 package.json 的工程目录打开 PowerShell：

```powershell
# 如果 Node 在 D:\Node 且尚未配置 PATH：
$env:Path = "D:\Node;" + $env:Path
npm.cmd ci
npm.cmd start
```

首次下载 Electron 需要联网；不要为下载关闭 TLS 校验。启动后仍可按旧方法创建指向 Electron + 工程路径的桌面快捷方式。无需另行全局安装 Electron。

## 配置 CloudBase

环境：emotional-newt-d5gg8duqi1ab13685，上海。

1. CloudBase → HTTP 网关 → 跨域设置 → 添加 `localhost:17383`。要求完整 Origin 的字段才填 `http://localhost:17383`。不加工程路径，保留 GitHub 和其他已有条目。
2. 打开桌面工作台的 AI 设置 → 云端同步，确认显示桌面版 0.2.0。
3. 输入当前环境的**客户端 Publishable Key**及已创建的应用用户名、密码，勾选同步现有记录，点击“登录并启用同步”。第二台电脑用同一账号。
4. 密码在认证后清空、不写入 SQLite 或仓库；官方 SDK 负责持久化设备登录会话并刷新 token。客户端可发布密钥和用户名保存在本机配置中。个人设备退出时使用“退出并停止同步”。

桌面窗口从仅绑定本机回环地址的固定来源 http://localhost:17383 加载内置静态文件，以支持 SDK 来源校验。它不是公网托管地址；没有开放数据库网络端口。其他进程占用该端口时应用拒绝启动，不能偷偷改端口导致来源失效。

## 同步行为及冲突

- 登录恢复后自动同步，每 15 秒检查；窗口恢复前台和联网时也会检查，可点“立即同步”。本机内容先显示，离线编辑仍存 SQLite。
- 上传前读取当前服务器版本。PATCH 同时匹配用户、模块和版本；触发器返回递增版本才确认成功。请求超时后下轮先读，若服务器已接受同一内容则确认，不盲目覆盖。
- **粒度为整个模块**，并非逐条自动合并。同一模块两端都有修改时暂停该模块，显示双方内容预览，可选“保留本机模块”或“采用云端模块”。选择前再次验证云端版本，另一版本自动留在本机 SQLite 的 sync_history 中；此阶段没有面向用户的历史恢复界面，需要协助恢复时保留数据库。
- 删除业务记录后上传该模块的新完整状态（例如空列表），保留服务器行版本；不硬删除云端模块行，避免旧设备重新上传已删除内容。
- 下载内容先做格式、归属及业务校验。正在编辑每日记录、未保存笔记、编辑弹窗或输入框有焦点时，延后应用远程更新，避免覆盖输入。保存并离开输入框后自动重试。
- 本机 SQLite 原子提交下载数据、同步基线及恢复副本。同步中产生的新编辑仍算待上传，不会被旧请求误记为已同步。
- 为避免账号混用，本机数据库首次绑定账号后禁止切换到不同账号；退出不删除数据或绑定。换账号需要单独处理数据库，不能简单清空同步基线。
- 只同步桌面版 SQLite；旧 GitHub Pages 浏览器 localStorage/IndexedDB 的历史迁移和安卓打包尚未实现。浏览器页面仍本地运行，不自动参与这次桌面同步。
- 关闭应用后不在后台运行同步。大笔记会整模块传输，日常少量记录适用；大型附件应后续转云存储。

## 两台电脑验收（先测试再录入日常数据）

1. A 新增测试备忘录，等待“已同步”。B 登录后检查能看到。
2. B 修改内容，等待“已同步”。A 切回窗口检查更新。
3. A 删除测试记录，B 确认删除结果。另测笔记、药箱和每日记录。
4. A 断网修改，关闭再打开仍能看到本机修改。恢复联网，B 确认收到更新。
5. 两端离线修改同一模块，联网后应出现冲突，双方内容保留；明确选择后再检查一致。
6. 退出并重开应用，确认不会自行恢复同步；再次登录原账号才能继续。

# 0.3.0 功能及正式安装版更新

储物柜新增“按格记录/补货”和“按物品记录/补货”。按格先选择柜子、格位和盘点/补货方式，再载入整格；盘点填当前总数，补货填新增数。同批全部通过校验后一次保存，失败不部分写入；移除表单行不删除原物品。旧版库存及同步记录无需重建。

物品可勾选“不会告急”，数量为 0 或 1 时也不会自动进入购买提醒；需要时点“调整为告急”，并可“取消告急”。此设置与手动状态随储物柜同步，两台电脑都应先升级再使用。临期及逾期备忘录单列到天气上方，晨起提醒在其上方；继续使用原有临期范围（至少 24 小时，或更长的所选提醒时长）。

## 第一次从源码版迁移为安装版

源码启动（双击 node_modules 中的 electron.exe + 工程目录）不能在应用内自动替换工程。这次首次安装正式 NSIS 安装包后，后续发布版本才可一键更新。

1. GitHub main 更新 package.json/锁文件后，Actions → **Build Windows installer** 自动构建；也支持 Run workflow 手动运行。
2. 构建会测试、生成安装包、blockmap、latest.yml，并上传一个 **Draft 草稿 Release**。仓库所有者在 Releases 中检查后点击 **Publish release**。草稿不被应用当成正式更新，不能仅上传源码 ZIP。
3. 下载该 Release 的 `Qijian-Setup-0.3.0-x64.exe`，先关闭旧版工作台，再安装。安装程序创建桌面快捷方式，不需要 Node.js；停止使用原来的源码快捷方式。
4. 数据库仍为 `%APPDATA%\qijian-workspace\workspace.sqlite`，原数据和登录配置继续保留。不要删除该目录；两台电脑分别安装。安装包没有代码签名证书，系统可能显示未知发布者，确认来自自己的仓库构建产物。
5. 如仍要临时使用源码版，覆盖新源码后须在工程目录运行 `npm.cmd ci`，本版新增 electron-updater 依赖，直接用旧 node_modules 启动会缺包。

## 后续应用内更新

AI 设置 → 应用更新 → 检查更新 → 下载安装并重启。安装版启动 10 秒后自动检查，并每 6 小时检查一次；不会静默下载或自动安装。主动点击后下载完成会保存笔记、检查未保存的每日记录/编辑弹窗/AI 操作；安全时安装并重启，未保存时保留下载、提示先处理编辑，再点“安装并重启”。普通退出不会偷偷安装更新。

更新使用 electron-updater 的 GitHub Releases provider，利用其 SHA-512 文件校验，保留 HTTPS 和默认签名校验行为。下载失败可重试，本地记录不清空。此下载链路依赖 GitHub 在所用网络中的可达性，国内网络可能不稳定；后续可把更新分发迁到国内 HTTPS 存储，但需另外配置发布域名与分发路径，不与 CloudBase 数据同步混为一项。

每次正式发布都应递增 package.json 版本，并同步锁文件版本；工作流拒绝覆盖已发布的同版本资产。只发布有意交付的草稿。发布草稿后，旧安装版会发现新版本；源码 ZIP 本身不会触发应用升级。

新增验证：`python tests/test_inventory_update.py`；`npm.cmd run test:desktop` 包含更新状态机检查。这些自动检查不代表实际 Windows 下载/安装/重启已在真实设备上验证，首次需用构建后的安装包联调。

# 0.4.0 多项生病状态与服药打卡

药箱可新增多项生病状态，每项可关联多种药箱已有的有效药品批次，填写每次用量（最多两位小数，必须与库存单位一致）及一日 1～6 次。一次显示“服药”，两次显示“早晨/晚上”，三次显示“早晨/中午/晚上”，四次增加“睡前”，五、六次显示序号。系统不推算剂量、服药间隔或盒/瓶/片换算。

首页在天气旁显示服药提醒，小屏上下排列。勾选实际已服用的次数后，点击“保存服药记录并扣减库存”，同一笔保存内一起更新药箱库存、每日次数账本和流水。相同日期/安排/次数具有固定标识，重复保存不重复扣减。取消已保存的勾选再保存，会按原记录的用量恢复库存；药品批次已删除或单位改变时拒绝自动恢复，需要先核对药箱。

- 日期默认为当天，可选择过去日期补记，不能记录未来；不同日期独立计数。跨日保留未保存选择，日期清晰显示。
- 旧文字状态保留为“原生病状态”（有名称时保留原名称），仍可编辑，再手动关联药品；不从旧文字自动猜测用量。
- 结束某项或修改其剂量、药品、频率不会抹掉历史。修改安排会生成新安排标识，原记录用原药品/单位/用量快照显示在“原安排 / 已结束安排的已保存记录”中，不会用新剂量回算旧库存。
- 勾选草稿保存在本机，不在未保存时扣库存或上传为服药记录。关闭/更新前提示保存；有未保存草稿时推迟应用云端药箱更新，防止覆盖正在核对的次数。其他模块仍可同步。
- 多个安排使用同一批药品时累计检查总用量；任一项数量不足、药品已到期或安排已改变，整笔保存失败，不部分扣减。
- 原有“消耗/补货”入口继续保留。首页打卡已经扣减的同一次实际服药，不要再手动登记一遍。
- 服药账本和库存位于同一药箱模块，沿用云端版本校验。两台设备同时修改会提示模块冲突，保留双方副本，明确选择一版；不把两份离线扣减简单相加。两台设备都应升级后使用此功能。

本次不需要重建 CloudBase 表。Actions 构建 v0.4.0 草稿后，在 Releases 发布；已安装 v0.3.0 的电脑可在 AI 设置 → 应用更新中检查、下载安装并重启。登录与 SQLite 路径不变。

验证：`npm.cmd run test:desktop` 新增用药计量、幂等、撤销、到期/库存保护、迁移与双设备冲突检查；`python tests/test_medication_ui.py` 检查实际页面多项设置、频次按钮、天气旁布局、库存变动、手动消耗、草稿恢复、历史剂量及手机窄屏；`python tests/test_workspace_sync.py` 覆盖模拟服务下的药箱账本与库存同步。真实 Windows 发布包仍需更新后验收。

# 0.5.0 文献方向、期刊指标、中文标题与阅读历史

- 文献时事新增“阅读历史”副页面。点击文章标题、DOI 原文、摘要或 AI 解读即记录；同一 DOI 再读会移至最前，最多保留最近 50 篇、原文跳转链接和阅读时的指标快照。历史本身是档案，不因期刊后来降分而删除。
- 英文标题下自动补充 AI 中文译名，原题保留。批量翻译按可见文献执行，阅读历史中的缺失译名也可自动补齐。需要 AI 设置中已有可用接口；未配置或请求失败时明确显示待生成，不把英文冒充中文、不虚构译文。
- 来源期刊名增大，并显示 IF 数值、指标年份、来源链接及“官网文本核验/用户对照来源核对”。**推荐文章的门槛固定为 IF > 4.0**；等于 4.0、未知或缺乏出处的指标均不放行。中文期刊无 IF 时可记录分区及其体系/年份，但按本次最终门槛仍不纳入推荐，不能以分区替代 IF。
- Crossref 不提供 JCR 影响因子，CiteScore/SJR/五年 IF 不能冒充年度 IF。本版不附未经核实的硬编码 IF。首次检索尝试读取所列 8 本刊源的官网明确标有年份的指标，最多缓存 30 天后重查；官网限制、跳转或文字格式无法确认时保留原带年份记录，缺乏记录则不放行。可展开“期刊指标”打开来源人工核对，并填写数值、年份、出处、证据摘录及核对确认。人工记录明确标为用户核对，不谎称已自动访问来源。
- 桌面版由主进程读取固定白名单中的出版社 URL，不能输入任意地址让它访问内网；不关闭 TLS、不放行未授权来源、不规避网站访问限制。浏览器版尝试正常 CORS 请求，失败可人工核对。当前开发环境访问出版方指标页返回 403，无法现场核实真实 IF，因此自动化检查使用合成指标；实际联网需在用户网络验证。
- “选择排序”支持相关度、期刊影响、发表时间。相关度优先使用 AI 对当前方向的评分，缺失时使用可解释的标题/摘要词匹配；期刊影响以已核对 IF 为主要依据（85%）及 AI 对方向、期刊定位的综合评估（15%）。不同年份始终标注，不能解释为同年官方榜单。AI 失败回退到已核对 IF，不捏造“AI 已评估”。
- “查找方向”先由现有 AI 接口输出有界 AND/OR/同义词组逻辑，保存时显示中文解释。之后 Crossref 请求、候选过滤及相关度评估都持续使用这套方向，不再偷偷加回固定城市条件；修改方向或重新分析失败时保留原已保存方向。检索范围仍是页面所列重点刊源，每刊最多 100 条候选；这不是全期刊全文搜索，也不能把没有抓到的结果称为没有发表。
- 阅读历史、方向/排序与核对指标作为两个独立模块保存在 SQLite 并通过现有 CloudBase 同步，发生同时修改时沿用模块冲突机制。AI 密钥仍只保留在各设备本地，文章缓存和 AI 中间缓存不作为业务模块上传。旧文献缓存保留原键，新版缓存用 v2 键且重新执行 IF/方向筛选，不能用旧缓存绕过门槛。

发布与安装沿用现有流程：Actions 构建 v0.5.0 草稿，在 Releases 发布后，正式安装版通过 AI 设置 → 应用更新下载安装。无需重建 CloudBase 表。

新增检查：`tests/literature.test.cjs` 验证布尔逻辑、IF 门槛/来源、指标抽取、50 篇历史、排序和受限代理；`python tests/test_literature_ui.py` 在合成 Crossref/AI 服务下验证中文标题、期刊字号、方向持久化、排序、历史副页、错误保留与缓存准入；`python tests/test_workspace_sync.py` 增加方向与阅读历史跨设备同步检查。真实发布包、官网指标及用户 AI 服务仍需更新后验证。

# 0.6.0 DeepSeek 官方搜索与网页抓取

依据用户提供的三份 Search/Fetch 文档接入 POST `/v1/tools/search`、`/v1/tools/fetch`，复用现有 DeepSeek API Key，不把它们误当成聊天模型自动联网参数。游玩人生默认勾选联网，可取消恢复普通离线知识整理。只接受官方 HTTPS Base URL（根地址或 /v1），正确处理 /v1，其他兼容服务仍可普通对话，但不擅自向其发送官方工具请求。

每次至多 1 次搜索（6 条，need_content=true）、2 次缺正文来源的补抓。搜索词与原问题按 Unicode 字符限制为128，搜索不附带已打卡清单。结果去重并限制正文长度；网页资料作为不可信内容，不执行其中指令。回答末尾追加实际返回的来源链接、北京时间查询时间及正文/摘要覆盖说明。工具失败不冒充联网成功；Fetch 失败只保留有标记的搜索摘要；搜索无结果不生成实时推荐。清除问答后迟到的搜索结果不会继续生成回复。

用户所附文档列出 Search、Fetch 各为每1000次成功且有结果的请求5元，另计模型 token；具体生效计费与账号权限以服务商控制台为准。此次没有使用用户真实密钥发请求，实网与用户账户可用性待更新后测试。先仅对游玩人生的联网勾选启用，不自动改变文献筛选或用药查询行为。

验证：`npm run test:desktop` 含URL、字符限制、失败、取消和工具资料检查；`python tests/test_search_ui.py` 使用模拟接口验证 Search→Fetch→chat 完整链路、来源附录、Markdown和 /v1 路径。
