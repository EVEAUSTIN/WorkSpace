# Windows 桌面版 0.2：SQLite + CloudBase 同步

本机 SQLite 为离线副本，CloudBase 同步备忘录、储物柜（含库存记录）、晨起提醒、每日记录、药箱、游玩打卡和笔记。使用现有 public.qijian_records 表及 RLS；无需重建表，不关闭权限校验。

AI API 密钥、客户端登录配置、天气及文献缓存和当前会话 AI 对话不作为业务记录上传。笔记内嵌的媒体随笔记 JSON 同步；尚未实现独立的大附件分块上传，服务端大小限制或超时会显示失败并保留本地内容，不代表附件已同步。

## 更新已有安装（两台电脑分别操作）

1. 关闭工作台窗口。
2. 重新下载 GitHub main 分支 ZIP，先解压到临时目录。
3. 将 ZIP 工程根目录中的文件和文件夹复制到原工程根目录，允许覆盖。保留本机 node_modules 文件夹；不要删除或覆盖 `%APPDATA%\qijian-workspace`，这里有数据库及会话数据。
4. 此次没有变更依赖版本，已有 node_modules 可直接使用。桌面快捷方式继续指向原工程目录，不要指向临时解压目录。
5. 再用快捷方式启动。如果首次安装、缺少依赖，才在工程目录运行 `npm.cmd ci`。

开发版与打包版显式使用相同的 userData 路径 `%APPDATA%\qijian-workspace`；移动工程文件不移动 SQLite 数据库。现有 SQLite 表保留，只新增 sync_history 历史表。

## 首次安装

使用 Node.js 24 LTS。在含有 package.json 的工程目录打开 PowerShell：

```powershell
# 如果 Node 在 D:\Node 且尚未配置 PATH：
$env:Path = "D:\Node;" + $env:Path
npm.cmd ci
npm.cmd start
```

首次下载 Electron 需要联网；不要为下载关闭 TLS 校验。启动后仍可按旧方法创建指向 Electron + 工程路径的桌面快捷方式。无需另行全局安装 Electron。

## 配置 CloudBase

环境：emotional-newt-d5gg8duqi1ab13685，上海。

1. CloudBase → HTTP 网关 → 跨域设置 → 添加 `localhost:17383`。要求完整 Origin 的字段才填 `http://localhost:17383`。不加工程路径，保留 GitHub 和其他已有条目。
2. 打开桌面工作台的 AI 设置 → 云端同步，确认显示桌面版 0.2.0。
3. 输入当前环境的**客户端 Publishable Key**及已创建的应用用户名、密码，勾选同步现有记录，点击“登录并启用同步”。第二台电脑用同一账号。
4. 密码在认证后清空、不写入 SQLite 或仓库；官方 SDK 负责持久化设备登录会话并刷新 token。客户端可发布密钥和用户名保存在本机配置中。个人设备退出时使用“退出并停止同步”。

桌面窗口从仅绑定本机回环地址的固定来源 http://localhost:17383 加载内置静态文件，以支持 SDK 来源校验。它不是公网托管地址；没有开放数据库网络端口。其他进程占用该端口时应用拒绝启动，不能偷偷改端口导致来源失效。

## 同步行为及冲突

- 登录恢复后自动同步，每 15 秒检查；窗口恢复前台和联网时也会检查，可点“立即同步”。本机内容先显示，离线编辑仍存 SQLite。
- 上传前读取当前服务器版本。PATCH 同时匹配用户、模块和版本；触发器返回递增版本才确认成功。请求超时后下轮先读，若服务器已接受同一内容则确认，不盲目覆盖。
- **粒度为整个模块**，并非逐条自动合并。同一模块两端都有修改时暂停该模块，显示双方内容预览，可选“保留本机模块”或“采用云端模块”。选择前再次验证云端版本，另一版本自动留在本机 SQLite 的 sync_history 中；此阶段没有面向用户的历史恢复界面，需要协助恢复时保留数据库。
- 删除业务记录后上传该模块的新完整状态（例如空列表），保留服务器行版本；不硬删除云端模块行，避免旧设备重新上传已删除内容。
- 下载内容先做格式、归属及业务校验。正在编辑每日记录、未保存笔记、编辑弹窗或输入框有焦点时，延后应用远程更新，避免覆盖输入。保存并离开输入框后自动重试。
- 本机 SQLite 原子提交下载数据、同步基线及恢复副本。同步中产生的新编辑仍算待上传，不会被旧请求误记为已同步。
- 为避免账号混用，本机数据库首次绑定账号后禁止切换到不同账号；退出不删除数据或绑定。换账号需要单独处理数据库，不能简单清空同步基线。
- 只同步桌面版 SQLite；旧 GitHub Pages 浏览器 localStorage/IndexedDB 的历史迁移和安卓打包尚未实现。浏览器页面仍本地运行，不自动参与这次桌面同步。
- 关闭应用后不在后台运行同步。大笔记会整模块传输，日常少量记录适用；大型附件应后续转云存储。

## 两台电脑验收（先测试再录入日常数据）

1. A 新增测试备忘录，等待“已同步”。B 登录后检查能看到。
2. B 修改内容，等待“已同步”。A 切回窗口检查更新。
3. A 删除测试记录，B 确认删除结果。另测笔记、药箱和每日记录。
4. A 断网修改，关闭再打开仍能看到本机修改。恢复联网，B 确认收到更新。
5. 两端离线修改同一模块，联网后应出现冲突，双方内容保留；明确选择后再检查一致。
6. 退出并重开应用，确认不会自行恢复同步；再次登录原账号才能继续。

## 安装包与验证

Windows 中 `npm.cmd run dist:win` 生成 NSIS 安装包到 dist，尚未签名、没有自动更新机制。开发与安装版共享数据库，不要同时运行。

```powershell
npm.cmd run test:desktop
```

开发者可运行：

```text
python tests/test_desktop_renderer.py
python tests/test_workspace_sync.py
python tests/test_cloudbase_auth.py
python tests/test_cloudbase_probe.py
```

自动测试使用合成身份和模拟 CloudBase HTTP，覆盖真实打包 SDK 登录、会话恢复、双设备 UI、删除、冲突和版本控制。不能替代实际 CloudBase 与 Windows 联调；不使用真实密码，也不自动上传用户业务记录。
